Identification under one fixed nominal LTI controller

One 20 m/s nominal model, one fixed LQI gain, one fixed prefilter for every client and speed. Only the prescribed yaw-rate reference depends on speed.

Goal and scope

Test whether controlled, path-inspired maneuvers provide accurate fixed-speed model estimates, and whether the same nominal model is useful as an additional OE start. This is a development diagnostic on three reused fleets. It does not yet compare fixed-LTI and learned-LPV controller performance.

All runs start from beta = r = 0 at nonzero fixed speed. A four-second curvature ramp establishes cornering; the 20-second fitting segment begins after 20 s settling and 4 s hold. The nominal controller remains active throughout, using noisy state measurements. No independent sideslip reference or spatial-path tracking claim is made.

Interpretation and next step

If the gate passes, inspect individual failures, saturation, tracking and start-to-start consistency before freezing this acquisition protocol for independent confirmation. If it fails, retain the successful gentle open-loop OE protocol and identify whether tracking, excitation, local approximation or optimization is responsible. Do not tune the fixed baseline to make LPV appear better.

The fixed LTI controller is a meaningful baseline for the later LPV controller comparison. That comparison must use identical held-out references, limits, sensing and evaluation criteria. LPV improvement remains an empirical question.

Canonical rollout uses the common quiet-segment validation center to preserve previous criteria; full-affine rollout uses training-fitted offsets. Both initialize each one-second prediction window at the exact simulator state. Available sideslip, known applied steering and fixed exact speed remain assumptions. Closed-loop noise timing and model mismatch require review.
