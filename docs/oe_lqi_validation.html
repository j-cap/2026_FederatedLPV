Frozen execution protocol · version 1

Do OE-derived LPV models improve matched LQI control?

This experiment connects the new identification results to the nonlinear control example. It uses the ten saved identification-confirmation fleets (1311–1320), all 30 vehicles per fleet, six controllers and two common maneuvers: 3,600 trajectories. The scientific trajectories are to be run locally. No outcomes are asserted here.

These fleets have already been examined for identification accuracy. This is a supporting control comparison, not a new independent control confirmation. No tuning, additional acquisition, OE fitting, clustering, seed replacement or model repair is performed.

1. Controllers and matching

MethodController modelRole

Only the ClosedOE4 condition is used. All methods use Q = diag(25, 50, 1000), R = 0.15, the acquisition controller’s weights. These are fixed before this experiment, not selected from its performance. They differ from the historical control test’s integral weight of 100.

The augmented state is [β, r, ξ], with ξ integrating r − rref. The requested steering is −K[β, r, ξ] + F rref; F is the model’s steady yaw-rate prefilter. All scheduled methods use LQI synthesis at 10, 12, …, 30 m/s and linear interpolation of K and F. The homogeneous A/B maps are used; OE nuisance offsets and fitted trajectory initial states are not inserted as deployment corrections.

Only saved model matrices enter controller synthesis. Vehicle parameters and ExactLPV references enter plant simulation and separate diagnostics. NominalLTI keeps its saved gain and prefilter exactly after a numerical consistency check.

2. Common maneuvers and simulation

The two 12-second reference profiles are inherited from experiment_10f_control_relevance.py and frozen as numeric arrays in code/config/paper_oe_lqi_profiles.npz. All methods and clients see exactly the same arrays. Requested yaw rate is rref = vκ, with requested lateral acceleration v²κ.

ManeuverPrescribed speedLateral-acceleration reference
ModerateSmooth cosine transitions 11 → 29 → 15 m/s.4 sin²(πt/12)[0.72 sin(2π·0.35t) + 0.28 sin(2π·0.72t + 0.4)] m/s².
HardSmooth cosine transitions 29 → 12 → 28 m/s.7[exp(−½((t−3)/0.40)²) − 1.10 exp(−½((t−6)/0.48)²) + 0.80 exp(−½((t−9.2)/0.55)²)] m/s².

Each run starts from β = r = ξ = steering = 0. The saved nonlinear tanh-tire bicycle plant is integrated by RK4 at 0.01 s, holding speed and applied steering constant within each step. Speed is prescribed; this is not a longitudinal-dynamics or full path-tracking validation. True-state feedback is noise-free to isolate the consequences of models learned from noisy identification data. No observer or sensor-robustness claim follows from this test.

All controllers share steering limits ±12°, rate limits 120°/s, and an integral limit of ±0.6 rad. The rate limit is inherited from the historical control stress test; acquisition used 30°/s. Rate limiting is applied before amplitude clipping. Conditional integration blocks an integral change that would worsen requested-versus-applied steering saturation. Sideslip exceeding 6° marks a finite trajectory infeasible but does not stop it.

3. Outcomes and failure handling

  • A failed synthesis node makes that method/client schedule unavailable for both maneuvers. Every node and its reason remain in the checkpoint. No fallback controller is substituted.
  • Full finite trajectories report yaw-rate RMSE and peak error, sideslip, steering effort, steering-rate effort, steering total variation, peak lateral acceleration, and limiter fractions.
  • Finite infeasible trajectories keep their full tracking metrics. Numerical failures keep their finite prefix and have null full-duration metrics; they are not assigned zero error or silently discarded.
  • Steering limiting is reported separately from feasibility. The sideslip and applied actuator bounds define feasibility; settling is not a requirement for these continuously varying references.
  • Frozen-speed spectral radii on 81 speeds are computed using the saved full-reference LPV map. They are diagnostics only: they neither gate rollouts nor certify stability of the nonlinear, varying-speed system.

After results are committed, report failures, feasibility and limiting before tracking improvements. Summarize finite cases equally by client, then fleet; give availability counts and paired fleet differences against NominalLTI, SmoothLocal and Global. Incomplete pairs must be identified explicitly. This protocol does not support confirmatory p-values or claims based on selectively excluding failed controllers.

4. Run locally — Windows CMD

Use the existing pinned federated_lpv environment. Preflight verifies frozen code, profiles, ten input checkpoints, shapes and package versions without designing controllers for the scientific fleets. Smoke uses only a nominal technical fixture in a spawned process and checks UTF-8 persistence and exact trajectory restoration.

git pull --ff-only origin main
conda activate federated_lpv
set OPENBLAS_NUM_THREADS=1
set OMP_NUM_THREADS=1
set MKL_NUM_THREADS=1
python code\experiments\paper_oe_lqi_validation.py preflight
python code\experiments\paper_oe_lqi_validation.py smoke
python code\experiments\paper_oe_lqi_validation.py run --workers 5
python code\experiments\paper_oe_lqi_validation.py status

The runner parallelizes by fleet and limits BLAS to one thread per worker. Progress prints after every saved client. Repeating run --workers 5 resumes incomplete fleets and skips completed ones. Each complete fleet has 30 client records and 360 cases. All ten fleets together must show 300 clients and 3,600 cases; “execution_complete” means every case was recorded, not that every controller succeeded.

An exclusive lock prevents overlapping run/restore jobs. After a hard crash, first stop all workers from that job. Only then, if the stale lock remains, remove results\data\paper_oe_lqi_validation\execution.lock and rerun the command. Do not remove a live job’s lock.

The numeric package versions are checked against environment.yml. If preflight finds a mismatch, update that environment using conda env update -f environment.yml --prune, then rerun preflight. It also requires Python 3.12.

The ten JSON checkpoints include frozen coefficients, assignments, plant parameters, actual schedules, synthesis diagnostics, outcome metrics, array hashes, protocol and provenance. Trajectory NPZ files live under the ignored results/data/paper_oe_lqi_validation/ folder. They need not be committed. Do not stage unrelated editor files.

After the push, provide the result status for analysis. We can then generate a separate HTML report and decide what Section VI can claim. No manuscript results are replaced before this assessment.

6. Restore ignored trajectories

python code\experiments\paper_oe_lqi_validation.py restore --workers 5

Restore uses saved controller schedules, parameters and frozen profile arrays; it performs no fitting or synthesis. Existing arrays are checked; missing arrays are reconstructed and saved only when all committed hashes and metrics match. JSON checkpoints remain unchanged. Use the original numerical environment; cross-platform numerical differences may prevent exact reconstruction and will be reported rather than accepted silently. Preserve original raw files until analysis is complete.
