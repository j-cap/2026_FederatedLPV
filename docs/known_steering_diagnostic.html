Known applied steering with noisy state measurements

A paired diagnostic of the completed continuous-calibration pilot. No results have been generated for this new condition at code handoff.

Question

How much does removing steering measurement noise improve the local A/B estimates when all state observations and physical trajectories remain exactly the same?

The known input is the steering applied after amplitude and rate limiting. The simulator applies this signal directly. This assumption would need revisiting if actuator tracking error or dynamics were introduced.

Precisely what changes

QuantityOriginal sensor conditionNew known-steering condition
Current and next statesNoisy measured traceExactly the same noisy trace
Steering recordsApplied angle + measurement noiseKnown applied angle
State centersQuiet measured-state meansIdentical means
Steering centerQuiet measured-steering meanQuiet applied-steering mean
Physical motion, timing, waveform, OLSIdentical

Both fitted matrices are scored on the same independent validation maneuver using a common center: its noisy-state means and its known steering mean. This prevents different validation centers from explaining a prediction difference. Frozen original prediction scores are also preserved separately.

Steering centering changes consistently with the steering measurement channel; the intervention is not restricted to the 2,000 fitting rows. No state-noise sample is redrawn and no noise setting in the original generator is changed.

Scope and interpretation

  • Reuse all three pilot fleets and all three amplitudes: nine jobs, 747 paired client–speed fits.
  • Verify every raw-array hash and reproduce the original sensor fit before adding its paired result.
  • Compare matrix errors, per-entry errors, one-second validation predictions, threshold pass counts and speed dependence. Save new local targets.
  • Report paired changes and three fleet-level means descriptively. This is post-pilot development, not independent confirmation.
  • Preserve the original selection, sources and results. Even a passing diagnostic does not automatically change the old confirmation protocol.
  • No group fitting, new estimator, controller experiment or new physical trajectory campaign.

If original NPZ files are missing, the restore command regenerates the original acquisition and requires exact saved array hashes. A platform-dependent mismatch is an error; the runner does not silently accept reconstructed replacements.

Run locally in Windows CMD

From the repository root, using the existing conda environment:

git pull --ff-only
conda activate federated_lpv
python code/experiments/paper_known_steering_diagnostic.py preflight
python code/experiments/paper_known_steering_diagnostic.py smoke
python code/experiments/paper_known_steering_diagnostic.py run --workers 5

Preflight reports whether all 747 original NPZ files exist. Only if some are missing, run this before run:

python code/experiments/paper_known_steering_diagnostic.py restore --workers 5

The original arrays should already exist on the machine that ran the pilot. Running again resumes from compatible checkpoints.

git add results/tables/paper_known_steering_diagnostic_seed*.json
git commit -m "Checkpoint paired known-steering diagnostic"
git push

python code/experiments/paper_known_steering_diagnostic.py analyze
start "" "report\known_steering_diagnostic.html"

git add results/tables/paper_known_steering_diagnostic_* report/known_steering_diagnostic.html
git commit -m "Analyze paired known-steering diagnostic"
git push

Outputs and technical checks

Results are saved separately under results/tables/paper_known_steering_diagnostic_*. The HTML result report is report/known_steering_diagnostic.html. This protocol page is docs/known_steering_diagnostic.html.

Technical tests check that only steering and its center change, adjacent state samples stay coherent, the applied input is used, zero steering noise produces identical paired fits, common validation centers are respected, and corrupted arrays or changed baselines are rejected:

python code/tests/test_known_steering_diagnostic.py

The smoke test uses a separate synthetic fixture in a spawned worker and saves no scientific results.
