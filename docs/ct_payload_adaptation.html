Does loading leave useful room for faster adaptation?

This experiment screens the opportunity for a later fleet-derived prior. It does not perform federated learning. The first question is whether a physically consistent loading change matters for control; the second is whether strong local identification resolves it after the first informative curve.

The three payload levels are repeated conditions on each of nine vehicles. This is not a 27-vehicle sample or a fresh confirmation fleet. The payload settings are controlled simulation assumptions, not a universal loading model. Real tire load dependence and CG movement are outside this first diagnostic.

The saved pre-change fits were obtained earlier from data acquired using full-state feedback. New post-change acquisition in this experiment is yaw-only observer-based feedback. The current test does not retroactively change how the earlier models were obtained.

Physical model and strongest simple local estimator

λ = added mass / pre-change mass
m+ = m− (1+λ)
Iz+ = Iz− + λ m− ρp²

p1 = Cf/m,  p2 = Cr/m,  p3 = m/Iz
p1+ = p1− / (1+λ)
p2+ = p2− / (1+λ)
p3+ = p3− (1+λ) / (1+λ p3− ρp²)
μ+ = μ−

The estimator knows the loading relation and payload radius. It estimates only λ in [0,0.5]. It does not receive the actual loading level, true plant parameters, sideslip, observer state estimates, future samples, or held-out reference responses. The upper bound is wider than the three simulated loading amounts. Pre-change parameter errors, including friction-estimate error, remain in all candidate models.

Because acquisition contains changing curvature, fitting uses the nonlinear continuous-time tanh bicycle equations rather than the old affine fixed-curvature OE approximation. Forces are expressed per unit mass, so the four existing physical ratios suffice. The model is propagated by RK4 at 0.01 s with the known applied steering held through each step. Physical initial sideslip and yaw are zero. No initial-state fitting, affine offset or sample-mean centering is performed.

J_T(λ) = mean over k=0,...,N(T) of
         [(predicted_yaw[k; λ] − measured_yaw[k]) / rad(0.03)]²

A 41-point grid over [0,0.5] is evaluated in a vectorized rollout. Every sampled interior local minimum is refined by bounded scalar optimization; both physical bounds remain candidates. Selection uses training loss only. All grid losses, optimizer attempts and boundary flags are saved. A flat unresolved objective is reported as uninformative, not as a successful zero-load estimate. The saved yaw-sensitivity norm is descriptive and is not a calibrated confidence interval under model mismatch.

Each prefix is copied before fitting. At T seconds there are T/0.01 applied inputs and one additional yaw sample. Thus the 4-second fit uses 400 inputs and 401 measurements. There is no 20-second settling segment silently excluded from the acquisition budget.

Comparators and fair control evaluation

MethodPost-change informationMeaning
PreviousNo updatePerformance of the existing identified controller/observer after loading
KnownChangeTrue loading fraction applied to the same imperfect pre-change modelBenefit available from knowing this change, without also correcting previous identification errors
Local4 … Local40Scalar estimate from the corresponding yaw/input prefixHow quickly local identification recovers performance

KnownChange is not an exact-plant oracle and not a guaranteed lower bound. A fitted λ may compensate for pre-existing model errors and outperform it. Keep signed differences instead of clipping them or forcing a percentage improvement.

Controller schedules use the inherited speed nodes, LQI weights Q=diag(25,50,1000), R=0.15 and prefilter convention. Updated schedules use the transformed physical ratios with the inherited cornering curvature 0.005/m. Observers use the corresponding straight-running physical models at the actual fixed test speed. All observers use the same Q/R/P0 and update timing as the previous observer pilot. The online integrator uses measured yaw; prediction uses applied steering.

Within a vehicle/loading/speed case, every method uses exactly the same sensor-noise realization. Acquisition and evaluation noise use different seed namespaces. Limits are 12° steering, 120°/s steering rate and 6° sideslip in evaluation. Acquisition uses 30°/s, 5° sideslip and reports a 6 m/s² acceleration check. The reference demand is not itself a bound on actual acceleration.

Previous and KnownChange are evaluated once per case/speed. Five local models add 15 runs, giving 21 per loading case and 567 overall. Baselines are reused only in analysis. Each evaluation starts from straight running with a fixed post-prefix model. This is not an online-adapting controller experiment and does not measure the accumulated control benefit of applying updates during the acquisition drive.

The runner sets OPENBLAS_NUM_THREADS, OMP_NUM_THREADS and MKL_NUM_THREADS to one before NumPy is imported. No separate set commands or new environment are required. Worker processes use Windows-compatible spawn; up to nine workers are allowed. The smoke command checks synthetic scalar recovery, a synthetic observed-control rollout, and UTF-8/NPZ checkpoint roundtrips. It does not execute a scientific loading case.

The run saves acquisition, each fit and each evaluation separately into a hash-protected per-loading-case JSON. Repeating the same run command resumes. Original acquisition arrays are compressed under results/data and ignored by git. No old raw identification trajectories are needed. A lock prevents simultaneous execution commands; remove a stale lock only after confirming no workers remain.

What to inspect and when to stop

First inspect acquisition feasibility, fitting failures, boundary estimates, controller synthesis failures, unstable local Jacobians and control limits. Full-duration finite violations stay in means. Missing full-duration metrics invalidate full aggregates rather than silently dropping failures. Average speeds, loading levels and vehicles equally.

The main plot shows yaw tracking RMSE, sideslip-estimation RMSE and steering-rate RMS against identification time, with the two fixed reference lines. The loading estimates and objective grids explain the result. All comparisons use absolute units as well as signed differences. Relative gap closure is undefined when Previous does not have positive headroom over KnownChange.

For transparency, the report includes fixed descriptive tracking-error tolerances 0.005/0.01/0.02°/s. It reports the first tested prefix after which all later tested prefixes remain within that tolerance of KnownChange at all three speeds, with both methods complete and feasible. These values are not automotive acceptance standards or an automatic success gate. Inspect estimation and control effort as well.

No method in this diagnostic learns a fleet prior. It establishes whether that next experiment is motivated.

Restore verifies existing acquisition arrays or reconstructs missing ones from committed inputs. Replay reconstructs a selected evaluation. Both require the saved canonical array hash to match exactly and preserve scientific checkpoints on mismatch. Use the original numerical platform for exact recovery: tiny differences between Windows and another platform can change byte hashes despite numerical agreement. A mismatch is never silently accepted as an original trajectory.

The report needs only committed JSON, not raw arrays. It embeds prespecified decimated previews for nominal_00 at 20% loading, plus aggregate tables and plots. Full-rate data determine all metrics.
