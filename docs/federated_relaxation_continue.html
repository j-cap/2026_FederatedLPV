Does the personalized-FL advantage survive convergence?

Continue the existing personalized fits, with the original data and objective. This is a numerical convergence check on the same three pilot fleets, not a new confirmation study.

Exactly what changes

ItemProtocol
MethodFedPersonal only: one learned fleet center and individual vehicle parameters.
Round budget30 total rounds, including the rounds already completed. This is not 30 additional rounds.
Fleets 1301 and 1302Resume their saved round-8 estimates, centers and optimizer history. At most 22 additional rounds each; stop earlier when the existing convergence criteria pass.
Fleet 1303Reuse its converged round-5 solution and saved predictions without refitting or resimulation.
UnchangedClient allocation, records and noise realizations, model, parameter bounds, penalty weights, per-client solver budget, convergence tolerances, and all evaluation conditions.
BaselinesReuse the saved LocalOE and NominalPrior metrics. No baseline fits are repeated. Global and FedGroups are not continued.

Copy the original personalized state into a separate checkpoint. Only the former budget-exhausted status is reopened. Each added round uses the same client-local nonlinear OE solver and server center update as the original implementation. Evaluation data never choose the stopping round, model or penalty.

The original stopping conditions require stable assignments, relative objective change below 10⁻⁶, maximum log-parameter movement below 10⁻³, and converged client solves. The existing local update budget remains 25 function evaluations. A finite model that reaches round 30 is evaluated with an explicit budget-exhausted status. An unavailable local update stops the fleet and preserves the failure; no replacement model is substituted.

Efficient and safe execution

Two worker processes run the two unfinished fleets concurrently. Thread limits are set internally; no OPENBLAS/OMP/MKL commands are needed. Each client update, completed round and evaluation case is checkpointed atomically with Windows replacement retries.

The runner reads the original ignored raw arrays when available and verifies their saved hashes. If arrays are missing, it reconstructs the original records and requires exact numerical-byte hash agreement. No new noise is sampled beyond reproducing the same seed-defined arrays. For missing test arrays, original predictions are reconstructed solely to verify the original full trace hash before evaluating the continued model.

Use the original machine and numerical environment, or provide the original raw arrays. A hash mismatch stops the run; it does not silently substitute approximately equivalent data. Source checkpoint hashes, implementation files, configuration and numerical package versions are locked. All continued outputs use a separate prefix; original files are never overwritten.

Repeated run commands skip completed work, including client updates inside an interrupted round. Only one continuation runner should be active. After a forced termination, delete results\data\paper_federated_relaxation_continue\run.lock only after confirming that no continuation process remains active.

Interpretation

First inspect convergence status and added rounds. Then compare the original and final FedPersonal prediction errors against LocalOE and NominalPrior, separately for each fleet and speed region. Peer-observed speeds remain the primary diagnostic; local-speed degradation and variation between fleets remain visible.

The report contains objective and parameter changes, added logical communication, paired prediction changes and before/after plots. Percent reductions are ratios of paired mean errors, not averages of casewise percentages. It does not apply a new significance threshold or declare a scientific pass.

This continuation resolves the finite-round ambiguity. It cannot establish that complementary-speed peers are more useful than same-speed peers, and it does not test closed-loop tracking. Those questions remain subsequent experiments.

Restore ignored continued traces

python code\experiments\paper_federated_relaxation_continue.py restore --seed 1301

Restoration performs no fitting, verifies the saved numerical-byte hashes and leaves the committed checkpoint unchanged. Reused predictions for fleet 1303 need no new arrays. Missing original arrays must also reconstruct exactly, as during execution.
