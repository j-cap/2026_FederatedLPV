One nominal LTI controller across the speed envelope

Development protocol for a focused comparison. The user runs the scientific pilot locally. Existing open-loop evidence and estimator sources remain frozen.

Purpose

Test a practical data-collection workflow: one nominal controller drives a smooth yaw-rate maneuver, each vehicle records its response and applied steering, and structured OE identifies the local physical A/B matrices. Separately test whether the same nominal model is a useful OE initialization.

This experiment does not yet establish an LPV control advantage. The later comparison must retain this fixed-controller baseline and use matched references, sensing, limits and evaluation metrics. Do not weaken or tune the nominal baseline to manufacture an LPV benefit.

Exactly one LTI model and one LQI controller

Use the nominal vehicle parameters m = 1500 kg, Iz = 2500 kg m², lf = 1.2 m, lr = 1.6 m, Cf = Cr = 80000 N/rad. Linearize through the existing small-angle bicycle matrices at 20 m/s and discretize at 0.01 s. Use Q = diag(25, 50, 1000) and R = 0.15, inherited from the paper's LQI settings. These are fixed in advance, not optimized on pilot outcomes.

Freeze the resulting matrices, gain and prefilter in the configuration. Preflight recomputes the design within numerical tolerance; execution uses the frozen coefficients to avoid platform-dependent synthesis roundoff in trajectories. The controller receives no client parameters, family labels, true equilibrium, or speed-scheduled gain. It uses noisy sideslip/yaw measurements and a clipped yaw-error integral. Known input means steering after rate and amplitude limiting.

The fixed law is uraw = −Kx y − KI ξ + F rref, with ξ integrating measured yaw minus reference. Integral magnitude is limited to 0.6; conditional integration prevents further windup into active steering limits. Gain K and prefilter F are constant for all vehicles and speeds.

Prescribed maneuver

Use exactly the three development fleets 1301–1303 and their original partial speed coverage: 249 client–speed cells, 83 per fleet. Every training and validation simulation starts at beta = r = 0 at its specified nonzero fixed speed. No acceleration-from-rest phase is modeled.

The reference smoothly approaches rref = v × 0.005 over 4 s. The controller stays active for the entire 20 s settling, 4 s hold and 20 s identification maneuver. During identification, add rexc = (0.3 m/s²)/v × s(t), where s(t) has unit peak. Training uses the original tapered multisine frequencies 0.2, 0.5, 0.9 and 1.4 Hz and deterministic phases. Validation uses the original tapered chirp from 0.15 to 1.2 Hz. This is a speed-dependent reference with fixed controller coefficients.

The reference is path-inspired through the small-sideslip relationship r ≈ vκ. There is no independent beta reference and no position/heading-error path tracker. Do not describe these as measured real-world trajectories or exact spatial-path tracking. Both beta and yaw remain available for feedback and identification.

Retain the original measurement-noise standard deviations, sampling, physical bounds and random-stream construction. The new and original protocols use matching underlying sensor-noise draws; physical states and applied inputs differ because acquisition changes. The unused noisy-input channel is saved for traceability; all new fits use the known applied steering.

OE still fits the 20-second segment beginning at 24 s, estimating its nonzero initial state and affine offset. The nominal start uses the same physical A/B matrices at 20 m/s at every speed, including both nominal A and B. The empirical mean initializes the offset and the first noisy state initializes the segment state. All ten parameters are then free. Keep the existing three starts and choose the lowest training loss among converged finite fits. No reference matrices or validation outputs enter fitting or selection.

OpenOE4 reuses the saved original three-start results and evaluates only the added start. ClosedOE3/4 share the same three-start fit. This avoids unnecessary repeated optimization. Open-versus-closed differences combine feedback and excitation-reference changes; they do not isolate feedback as a single intervention.

Acceptance and failure reporting

Preserve the existing requirements: relative matrix error ≤10%, canonical one-second normalized rollout RMSE ≤0.5, better prediction than persistence, ≥95% accurate cells, and all physical/settling checks passing. The physical check includes zero excitation-segment limiter activations. Record both canonical and complete-affine prediction errors, all optimizer attempts, controller tracking errors, rate-limit activity, physical maxima and raw-array hashes. Clean data are evaluated but never used to initialize OE.

Technical smoke finding: the nominal-design vehicle at the envelope edges activates the steering-rate limiter under noisy feedback. This is explicitly recorded as a failure of the inherited no-clipping acquisition criterion, even when the applied-input bounds are satisfied. No thresholds, gains or noise levels were changed after this check. The pilot will quantify the issue across vehicles and determine whether identification remains accurate. Limiter activity is not, by itself, evidence that LPV control is necessary; feedback-noise handling may require separate development.

Nonfinite simulations are recorded as failed cells; failed fits stay in accuracy denominators. No silent fallback to ground truth, no dropped vehicles, and no automatic confirmation unlock. Independent confirmation seeds remain untouched. Stop and review this pilot before replacing the paper's acquisition protocol.

Windows commands

git pull --ff-only
conda activate federated_lpv
python code/experiments/paper_fixed_lti_identification.py preflight
python code/experiments/paper_fixed_lti_identification.py smoke
python code/experiments/paper_fixed_lti_identification.py run --workers 3

There are three independent fleet jobs; more than three workers provides no additional parallelism. Each fit limits BLAS threads internally. Completed fleet checkpoints are resumed without rerunning them. Unfinished fleets restart.

If original gentle-pilot arrays are missing, restore their exact committed hashes first:

python code/experiments/paper_fixed_lti_identification.py restore --workers 3

The new ignored trajectories can later be reconstructed from saved recipient parameters, seeds and frozen controller coefficients:

python code/experiments/paper_fixed_lti_identification.py restore-new --workers 3

Reconstruction verifies every array hash and refuses approximate or corrupted data.
